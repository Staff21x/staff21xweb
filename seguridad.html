Alcance y propósito

Este documento describe el modelo de seguridad de la información bajo el cual operan los Trabajadores Digitales y los sistemas desarrollados por Staff21x. Cubre arquitectura técnica, gestión de datos, controles de acceso, trazabilidad y cumplimiento normativo.

Staff21x opera sobre la infraestructura de Resility, empresa especializada en ciberseguridad con soluciones de CyberSOC-as-a-Service. Toda la arquitectura tecnológica de Staff21x cumple con los estándares de seguridad definidos y operados por Resility.

🎯

Este documento está dirigido a equipos de seguridad de la información, áreas de compliance y departamentos de tecnología de organizaciones que evalúan la incorporación de soluciones Staff21x en sus procesos operativos.

// 02

Definición técnica — Trabajador Digital

Un Trabajador Digital es un agente de inteligencia artificial configurado para ejecutar tareas operativas específicas dentro del entorno tecnológico del cliente. Opera exclusivamente mediante interfaces de programación autorizadas (APIs), sin acceso directo a bases de datos, sistemas de archivos internos, ni infraestructura no declarada en el contrato de implementación.

🔒

Un Trabajador Digital no copia, replica ni retiene las bases de datos del cliente. Procesa únicamente la información que el cliente expone explícitamente a través de las APIs configuradas durante la implementación.

Modelo de interacción

El flujo de información sigue estrictamente la siguiente cadena:

Sistema del cliente
→
API autorizada
→
Trabajador Digital
→
Respuesta / Acción
→
Sistema del cliente

// cada eslabón opera con autenticación, cifrado en tránsito y logs de auditoría · el agente nunca inicia conexiones salientes no declaradas

Gestión de datos

Datos que recibe

✓
Exclusivamente los datos expuestos por el cliente vía API en el contexto de la tarea asignada
✓
Consultas, mensajes y registros operativos específicos definidos durante la configuración
✓
Ningún dato es transmitido fuera del alcance técnico acordado en la implementación

Datos a los que NO accede

✗
Bases de datos completas o parciales fuera del scope de la API configurada
✗
Credenciales de sistemas, certificados o material criptográfico del cliente
✗
Archivos internos, repositorios de documentos o sistemas no incluidos en el contrato
✗
Información de otros clientes o entornos multi-tenant del cliente

Retención de datos

✓
Los datos procesados durante una sesión no se almacenan en servidores de Staff21x ni de Resility, salvo configuración explícita y documentada acordada con el cliente
✓
No existe base de datos de clientes en Staff21x con información operativa del cliente final
✓
Los logs de operación son configurables y auditables por el cliente según sus propias políticas de retención
// 04

Arquitectura de seguridad

🔐 Cifrado y transmisión

✓
Toda comunicación cifrada mediante TLS versión mínima 1.2
✓
No se permiten conexiones no cifradas en ningún punto de la integración

🎯 Control de acceso

✓
Principio de mínimo privilegio — accede únicamente a endpoints declarados explícitamente
✓
Autenticación mediante tokens o claves API con rotación periódica recomendada
✓
Sin acceso a nivel de sistema operativo, red interna ni infraestructura subyacente del cliente

📋 Trazabilidad y auditoría

✓
Toda interacción genera logs auditables: timestamp, tipo de operación, endpoint, resultado
✓
Los logs no incluyen el contenido de datos sensibles procesados
✓
El cliente puede solicitar exportación de logs en cualquier momento

🏗️ Aislamiento de entornos

✓
Cada implementación opera en un entorno aislado — sin comunicación entre instancias de clientes distintos
✓
Entorno de producción separado de entornos de desarrollo y pruebas

Marcos normativos y estándares

La infraestructura de Resility, sobre la cual opera Staff21x, está alineada con los siguientes estándares internacionales de seguridad de la información:

PCI DSS
Payment Card Industry Data Security Standard
Estándar de seguridad para datos de tarjetas de pago (Visa, Mastercard, Amex). Aplica a cualquier flujo que toque datos de pago.
→ cifrado de datos · control de acceso · auditoría de red
HIPAA
Health Insurance Portability and Accountability Act
Ley federal de EE.UU. para protección de información de salud. Estándar de oro global para datos sensibles.
→ cifrado en tránsito (TLS) y en reposo · logs inmutables de acceso
NIST 800-53
National Institute of Standards and Technology
Catálogo de controles de seguridad del gobierno de EE.UU. Base técnica para sistemas críticos.
→ reglas de detección · respuesta a incidentes · protección de comunicaciones
GDPR / RGPD
Reglamento General de Protección de Datos
Reglamento europeo de protección de datos personales con alcance extraterritorial.
→ privacidad por diseño · recolección mínima · derecho al olvido

Responsabilidades compartidas

La seguridad de una implementación es una responsabilidad compartida entre Staff21x y el cliente. Este modelo define claramente el alcance de cada parte:

Staff21x / Resility
Seguridad de la infraestructura de ejecución del agente
Cifrado en tránsito en la capa de comunicación
Monitoreo y detección de anomalías en la plataforma
Actualizaciones de seguridad del agente y su entorno
Aislamiento entre entornos de distintos clientes
Respuesta a incidentes de seguridad en la plataforma
Cliente
Seguridad de los sistemas propios y APIs expuestas al agente
Gestión de credenciales y tokens de acceso del lado del cliente
Definición del alcance de datos que el agente puede acceder
Políticas internas de retención y auditoría de logs
Seguridad física de los dispositivos que acceden al sistema
Cumplimiento normativo específico de su industria
